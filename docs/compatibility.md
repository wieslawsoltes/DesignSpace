# Compatibility matrix — 0.1 preview

DesignSpace is an independent Blend-style designer. Familiar panels do not imply complete or pixel-exact Microsoft Blend, WPF, WinUI or Visual Studio compatibility. This matrix separates implemented authoring from preserved-only markup and unqualified runtime behavior.

## Template property triggers

Templates and styles can preview supported Trigger/MultiTrigger declarations without executing imported code. Named parts remain isolated per instance, owner local values retain precedence, and disabled ancestors constrain condition values. **Test controls** supplies transient pointer/keyboard/check state, while **Sample** creates editable template source. Native WPF comparisons cover defined effective-value and reset combinations, not complete runtime or Blend UI equivalence. See [template authoring, API and limitations](template-triggers.md).

## Effects and preview performance

The Effects panel edits a local replacement, not a shared resource. None explicitly suppresses inherited effects; Reset to style removes the local override. Artboard preferences can suppress filters globally or above a zoom limit without changing XAML or PNG export. Native and software-reference modes are distinct, and WPF soft-edge profiles are measurements rather than blanket equivalence passes. See [effect semantics and evidence](effects.md).

## Document workspaces

New/Open add tabs rather than replace the active design. Documents keep isolated in-memory history, selection, viewport and supported drafts while sharing one active control tree and renderer. Save All returns to the original tab; Close protects unsaved data and unapplied drafts. Workspace files retain the entire open set, including invalid source as inert text, but not undo history or active animation/pointer gestures. Browser-reserved shortcuts remain host-dependent. See [workspace contracts, limits and qualification](workspaces.md).

## Stroke authoring

Use **Stroke** to edit base stroke settings, preview drafts, and apply changed fields in one transaction. Invalid or stale drafts cannot overwrite the document. The native renderer and picker share the outline, including dash gaps and independent caps. Empty Brush removes the stroke; Transparent remains hittable, while a null brush and Width zero do not. Outline conversion retains identity and undo, but protects filled, locked, style-dependent and animation/state-linked objects. See [stroke semantics, limits and host contracts](strokes.md).

## Vector authoring

**Pen (P)** creates a draft: click for corner points and drag for cubic tangents. Click the first point to close, press Enter to finish an open path, or Escape to discard the draft. Backspace removes the last draft point. The document changes once on completion. **Pencil (Y)** records and simplifies one freehand contour; it remains an editable path.

**Direct Selection (A)** edits anchors and tangent handles. Shift-click toggles anchors and Shift-drag adds points inside a marquee. Drag any selected anchor to move the selection together. Ctrl+A selects all anchors in the current Path; Ctrl+Shift+A clears them. Arrow keys nudge selected points by one artboard unit (Shift: ten); Delete removes the selected anchors in one transaction. Escape cancels an active point drag or marquee without modifying the document. Clicks without movement do not snap points or create history. Tangent handles are edited individually; Alt breaks the link to an adjacent cubic handle. Click an edge and use Delete to remove that segment without connecting across the gap. Pen clicks on existing anchors remove them; clicks on edges subdivide them. Line, quadratic and cubic subdivision is exact; arc insertion retains elliptical arc parameters with corrected radii.

The **Paths** panel aligns and distributes selected anchors in artboard coordinates, including paths under transformed ancestors. Point selection itself is transient UI state, not a document edit: completed geometry edits are undoable, but undo/redo clears the point selection, and recovery saves geometry rather than selection. A batch deletion that leaves fewer than two anchors in a figure removes that figure; it does not delete the Path object. Batch movement carries cubic tangents with their endpoints. A shared quadratic control follows the average displacement when both endpoints move, so selecting both does not translate it twice.

Use **Paths** or the **Path** menu for conversion and combinations. Canvas siblings are transformed into their common parent's coordinates. Subtract uses the bottom shape minus the upper operands. The bottom shape supplies appearance, and results remain editable paths. Divide currently requires exactly two shapes. Make compound uses EvenOdd filling; Break apart separates contours and can therefore remove the visual effect of holes. Destructive operations reject locks, animation/state references and unresolved explicit style/opacity/effect combinations rather than silently discarding them.

A path's `Stretch=None` preserves its coordinate system; the other stretch modes transform geometry into the layout box without multiplying stroke thickness. Interactive rectangle resizing transforms path geometry explicitly. Geometric clipping maps the top shape to the target's local coordinates and removes the mask shape in one undoable transaction.

Arcs remain native elliptical segments for ordinary rendering and simple translation/uniform scaling. Flattening an arbitrary affine transform into editable path data approximates arcs with cubic segments spanning at most 45 degrees; it is not algebraically exact. Boolean results inherit Skia's floating-point geometric semantics. Direct editing is a base-document operation, not a new animation or state-recording mode.

## Numeric keyframe composition

The Animation inspector authors additive base offsets and cumulative final-key contributions across child repetitions. Flags, timing and keys apply atomically; invalid drafts follow document tabs and recovery without changing the model. Parent repetition restarts children, and intrinsic parent reversal selects the preceding child endpoint at exact repeat boundaries. Simple DoubleAnimation composition remains preserved because its cumulative delta differs from keyframe semantics. See [composition formulas, API contracts and native reference scope](animation-composition.md).

## Independent animation tracks

The **Animation** panel edits child-clock timing and selected-key values/easing as one revision-guarded transaction. The spline graph has draggable handles and numeric control points. Timeline diamonds show the first forward child iteration in parent time; key fields remain child-local. Unsupported arbitrary nested timelines remain preserved, not simulated. [Animation guide and native WPF reference-test scope](animation.md).

## Editing time versus playback time

The timeline ruler uses the storyboard's original `Duration`; explicit child-track key fields use that child's local interval. Scrubbing bypasses parent playback timing but keeps child clocks. Playback applies `BeginTime`, `SpeedRatio`, `AutoReverse` and repeat settings through `StoryboardClock`. A completed integral forward repeat holds its final key rather than wrapping to the first one; a completed reverse cycle returns to its start. `FillBehavior=Stop` removes the animation contribution and restores the underlying base/state values.

Choose **Timing** in the timeline, edit the settings and use **Apply timing**. Shortening a duration cannot silently remove keyframes. Enable **Scale keyframes** to proportionally retime the existing keys, or move them before shortening. Invalid settings leave the document unchanged.

In **States**, select a state and enable **Record state** to edit overrides from Properties. The inspector shows the state context and effective values. Reset removes the selected override, and undo restores it. Outside state recording, ordinary edits still change base values. Inline gradient creation is blocked during state recording; use a solid color or resource reference instead.

## Visual-state groups and generated transitions

The States panel lists groups and their member states. Select a group header to choose where new states are created; use the name field and Rename for state renaming. **Transitions** opens the reusable rule editor and group create/rename/delete commands. Deleting a group removes its states and rules as one undoable transaction. Renaming a state updates transition From/To selectors, and deleting it removes referring rules.

Enable **Animate** in States (off by default) to preview generated transitions. A group's exact From/To rule wins over a To-only rule, then a From-only rule, then its default rule. Use `*` in the editor for any state; exported XAML omits that selector. Durations are finite seconds from zero to one day. Linear and cubic EaseIn/EaseOut/EaseInOut are supported. With no matching rule, zero duration, or state recording enabled, state changes are immediate.

One state per group can be active. Different groups can animate disjoint properties concurrently; the same property targeted by two active groups is rejected rather than given an undocumented precedence. A group's Base button returns only that group to base values; the top Base button resets all groups. Numeric properties with finite endpoints and solid brush colors interpolate. Missing destination setters return to base values. Auto sizing, gradients, unresolved expressions and other non-interpolatable values are held until completion rather than converted to bogus numeric values. Color interpolation uses sRGB ARGB channels; scRGB literals are converted at the endpoints, not interpolated in a linear-light color space.

Changing destination during playback samples the current preview as the new starting point. Preview frames do not change the document, source or undo history. Enabling state recording, editing the document, completing preview, or unloading the States control stops active transition callbacks. Active states and in-flight transitions are transient and are not restored from saved files. Old version-1 files missing only the newly added group metadata are migrated to `DesignSpaceStates`; explicitly null metadata is not silently repaired.

Group extraction from root-level XAML is all-or-nothing. Supported setters, group names, GeneratedDuration and CubicEase round-trip. Explicit transition/state storyboards, custom easing, adaptive triggers, unsupported attributes and invalid selectors keep the whole group as inert preserved XML. Nested template-local state groups are not extracted into this document-level editor. Preserved-only markup is not a working runtime. Export remains Uno/WinUI-oriented; this is not WPF/Blend differential qualification.

## Built-in easing functions

Numeric keys support all eleven WPF built-in easing families, directions and bounded literal parameters. Simple DoubleAnimation functions with conventional endpoint values import as keys; discontinuous cases such as Power=0 stay preserved rather than changing their start/end behavior. The Animation panel includes parameter authoring, an overshoot-aware curve preview and document-specific draft recovery. Native Windows tests compare scalar functions and animated values, including discontinuous Power=0 edge cases. Unknown/custom functions and out-of-budget parameters remain preserved markup. See [easing semantics and qualification](easing.md). This does not add arbitrary nested timelines or color/object/point animation, nor prove Blend UI pixel equivalence.

## Import policy

Imported XAML constructs data, never executable assemblies or arbitrary markup extensions. Retention is not behavioral support. Supported flat timing syntax is extracted into the editable timeline; unsupported nested timing, acceleration ratios or custom easing stays as XML rather than losing metadata. Explicit parent durations can clip supported child tracks while retaining all child-local keys; the parent is not silently lengthened.

Native documents preserve designer identities and state more completely than XAML. Newly added timing fields have defaults so earlier version-1 native files remain readable. Copy/paste remaps model identities and names but does not rewrite every arbitrary reference embedded in retained XML as a semantic dependency graph.

## Limits and evidence

Model documents are limited to 20,000 nodes and 64 nesting levels. XAML/native codecs limit input to 8 MiB of characters; the application also checks import byte sizes. Sample JSON is limited to 256 KiB and PNG export to 32 megapixels. A text block is limited to 32,768 UTF-16 characters. Glyph and line caches retain at most 512/128 entries with estimated 8 MiB/2 MiB cost budgets. Vector paths additionally limit data to 1 MiB of characters, 8,192 segments and coordinate magnitude of one billion units. Hit-test tessellation is capped at 131,072 edges and recursion depth 12. Native path caching uses at most 256 entries with an estimated 8 MiB budget. These are safety and cache budgets, not performance guarantees at every limit.

CI runs portable editing, compatibility, image/layout/shaping, vector geometry/pixel fidelity and trimmed-persistence tests. Published-browser checks use real pointer and keyboard input and retain screenshots, logs, state snapshots and a CPU allocation comparison. Windows/macOS/Linux application results are compilation checks. The separate Windows WPF animation reference executable checks its documented numerical cases only; it does not qualify Uno desktop interaction or full Blend behavior. Chromium uses software-backed WebGL; no physical-GPU, all-browser, screen-reader, native-dialog or independent security certification is implied.

## Largest remaining parity areas

The remaining substantial areas are complete template/style/behavior semantics; multi-object point selection, advanced tangent/brush authoring; rich typography and bidi/fallback; nested animation, explicit state-transition storyboards and automatic triggers; full solution/project tooling and simultaneous document surfaces; native multi-window docking; accessibility; and cross-platform runtime/GPU qualification. Extend shared libraries and tests rather than introducing a separate browser imitation.
